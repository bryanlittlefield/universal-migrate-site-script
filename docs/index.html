How it works

A run, start to finish

Nothing is changed until the configuration validates, the preflight passes and you say go. After that the steps run in a fixed order and every one of them is reported with its real result.

The steps

What each step does

Same order as the original script. Interactively you confirm each one; the plan at the top of a run shows which will be skipped and why. ./migrate.sh --list-steps prints the ids.

1

Clear local web root

clear-web-rootopt-inall platforms

Deletes everything inside local_web_root, dotfiles included, so the sync starts from nothing. Off by default; interactively you must type the directory name to confirm.

Under the hood
  • Refuses /, ., $HOME, relative paths, anything shallower than two levels, and the script's own directory or any parent of it.
  • Runs find "$root" -mindepth 1 -maxdepth 1 -exec rm -rf -- {} +, then sets WEB_ROOT_CLEARED so step 2 is skipped automatically.
  • Enable with --with clear-web-root, --only clear-web-root, or run_clear_web_root='true'.
2

Enable maintenance mode (local site)

maintenance-onWordPressLaravel

Visitors of the local site see a maintenance notice while files and data are replaced.

Under the hood
  • WordPress: writes .maintenance containing <?php $upgrading = time(); ?>, which never expires (core's own file expires after 10 minutes, shorter than most syncs). Laravel: php artisan down --retry=60.
  • Skipped when the web root was just cleared or does not exist yet. If the run aborts with maintenance still on, the exit message says so.
3

Sync files from remote

sync-filesall platforms

Copies the remote web root with rsync, skipping caches, backups, dumps and whatever else is in config/rsync-exclude.txt. Shows a progress bar and writes a per-file log.

Under the hood
  • rsync -rlpt --human-readable --stats --partial --exclude=/.maintenance --exclude=.git/ --exclude='*.sql' --exclude-from=config/rsync-exclude.txt --log-file=logs/rsync-<ts>.log -e "ssh -p <port> [-i key]" user@host:/remote/root/ /local/root/
  • rsync_mode adds --ignore-existing or --delete; sync_mode=code excludes the uploads dir, uploads includes only it. --info=progress2 is used when the terminal and rsync version allow.
  • Exit 23/24 (files vanished or unreadable mid-transfer) is a warning; any other non-zero exit fails the step.
4

Migrate database

migrate-dball platforms

Exports the remote database, backs up the current local one, drops the local tables and imports the fresh copy. Tables in config/db-tables-exclude.txt arrive empty (structure only); tables in db_preserve_tables keep their local data (for example wp_options, so local URLs and settings survive). Details in Database below.

Under the hood
  • SHOW TABLES first, to expand wildcard excludes into --ignore-table=db.table and to compare counts afterwards.
  • One mysqldump pass, or two when tables are excluded: --no-data --skip-triggers for structure, then --no-create-info with the ignores for data.
  • Stream filter: strip DEFINER=… and SQL SECURITY DEFINER, drop the MariaDB sandbox line, map utf8mb4_0900_* collations when the local server needs it.
  • Backup to dumps/<db>-backup-<ts>.sql.gz, drop every table and view listed in information_schema, import wrapped in SET autocommit=0; unique_checks=0; foreign_key_checks=0 … COMMIT with --max-allowed-packet=1G and a pv progress bar.
  • db_preserve_tables (wildcards resolved against the local table list): mysqldump --add-drop-table of those tables before the drop, their names added to the export's --ignore-table list, and the saved SQL replayed after the import.
5

Update app config and URLs

app-configWordPressLaravel

Points the site at the local database and domain. WordPress gets a full search-replace of the old domain (including the www. form and the scheme if it changed); Laravel gets its .env updated.

Under the hood
  • WordPress: wp config set for DB_NAME DB_USER DB_PASSWORD DB_HOST WP_HOME WP_SITEURL, then wp search-replace --recurse-objects --skip-columns=guid --all-tables --report-changed-only --skip-tables=<list> for each pair in order: www.old → new, old → new, config/domain-pairs.txt, then https://new → http://new (and the \/\/ escaped form) when schemes differ.
  • Multisite: detected with wp core is-installed --network; search-replace runs with --network --url=… and DOMAIN_CURRENT_SITE is updated.
  • Laravel: APP_URL APP_ENV APP_DEBUG DB_HOST DB_PORT DB_DATABASE DB_USERNAME DB_PASSWORD are replaced in place or appended; artisan key:generate --force runs if APP_KEY is empty.
6

Remove WP Engine config and host drop-ins

host-cleanupWordPress

Takes out the WP Engine lines in wp-config.php (after backing it up), the WP Engine must-use plugins, and the object-cache / advanced-cache drop-ins that only work on the host.

Under the hood
  • Config edits only happen if the file contains WPE_, PWP_, wpengine or is_wpe. Backup: wp-config.php.bak-<ts>. Lines matching the regexes in config/wpe-config-patterns.txt are deleted; WP_HOME/WP_SITEURL are left alone because step 5 just set them.
  • mu-plugins from config/host-mu-plugins.txt are removed if present; object-cache.php and advanced-cache.php go when wp_remove_dropins=true.
7

Install Kinsta MU plugins

kinsta-pluginsopt-inWordPress

Only when the destination is Kinsta. Downloads and unzips Kinsta's must-use plugins into wp-content/mu-plugins.

Under the hood
  • curl -fsSL --retry 3 -o … $kinsta_mu_plugins_url, unzip -oq … -d wp-content/mu-plugins, then checks that kinsta-mu-plugins.php exists. Skipped if already installed unless kinsta_force_reinstall=true.
8

Apply local WordPress settings

local-hardeningWordPress

Makes the copy behave like a development site: environment type, debug mode, search engines discouraged, host-only plugins deactivated, and optionally a local admin user you can log in with.

Under the hood
  • wp config set WP_ENVIRONMENT_TYPE local, wp config set WP_DEBUG true --raw, wp option update blog_public 0.
  • Each slug in config/host-plugins-deactivate.txt is checked with wp plugin is-installed before wp plugin deactivate.
  • With wp_local_admin_user set: wp user create … --role=administrator or wp user update, plus wp super-admin add on multisite.
9

Flush caches and permalinks

cache-refreshWordPressLaravel

Rewrites and caches are rebuilt so the first page load reflects the new domain.

Under the hood
  • WordPress: wp rewrite flush, wp cache flush, wp transient delete --all, and wp kinsta cache purge if that command exists. Laravel: php artisan optimize:clear.
10

Verify the migrated site

verifyall platforms

Checks that the site loads, that its URLs point at the local domain, that the table count matches the remote, and that the local domain answers over HTTP. Only hard failures fail the step; the rest are warnings.

Under the hood
  • wp core version (failure = step fails), wp option get home must contain local_domain, optional wp db check (verify_db_check), artisan --version for Laravel.
  • curl -ksS -o /dev/null -w '%{http_code}' --max-time 20 <scheme>://<local_domain>/; 200, 301 or 302 pass, anything else is a warning because the domain may not resolve from the machine running the script.
11

Disable maintenance mode (local site)

maintenance-offWordPressLaravel

Removes the maintenance notice. The site is live locally.

Under the hood
  • Removes .maintenance or runs php artisan up.
Setup

Up and running in five steps

You need SSH access to the remote server, its database credentials, and a local web root and database to land in. The script checks everything else for you.

1

Have the tools

On the machine that will host the copy (usually a Linux container, but a Mac works too):

bash 3.2+sshrsync 3.1+mysql + mysqldumpgzip wp (WordPress)php (Laravel) optional: pv · curl · unzip · sshpass

Debian/Ubuntu: apt-get install -y rsync mysql-client pv sshpass unzip curl, and WP-CLI from wp-cli.org. The preflight names anything missing; nothing is installed for you.

2

Clone and create your .env

git clone https://github.com/bryanlittlefield/universal-migrate-site-script.git
cd universal-migrate-site-script
cp .env.example .env

.env is git-ignored. Quote values with single quotes so passwords with special characters survive. An .env from the original migrate-site-script works unchanged.

3

Everything else has a sensible default. The full list with comments is in .env.example.

4

Run the preflight

./migrate.sh --check

Verifies the tools, logs in over SSH, checks the remote web root, connects to both databases and compares disk space. It changes nothing, so run it as often as you like.

What it runs
  • ssh -n … 'echo ok' and test -d <remote_ssh_web_root>
  • Remote DB: opens the tunnel (or runs mysql on the remote) and executes SELECT 1; local DB: SELECT 1 then SHOW DATABASES LIKE
  • du -sk of the remote root against df -Pk of the local target (only in --check or with preflight_disk_check=true)
5

Migrate

./migrate.sh            # interactive: confirm each step
./migrate.sh --dry-run  # rehearse: prints every command, changes nothing
./migrate.sh --yes      # unattended

When it finishes, read the report. It is printed on screen and saved to logs/migrate-report-<timestamp>.txt with one line per step, its real result and how long it took. The full output is in logs/migrate-<timestamp>.log.

Database

Where the database comes from

Two ways to get the dump, chosen with db_export_method. Both stream the SQL through the same filter and land it in dumps/. The remote password never appears on a command line.

Then, locally

List remote tablesexpands wildcard excludes, remembers the count
Exportone pass, or structure + data when tables are excluded
Back up local DBdumps/<db>-backup-<ts>.sql.gz
Save preserved tablesdb_preserve_tables, if any
Drop local tablesand views, from information_schema
Importbulk settings on, progress bar, COMMIT at the end
Restore preserved tableslocal data back in place
Compare countsremote vs local, reported in verify
Client flags are detected, not guessed
  • The right SSL flag comes from mysql --version / mysqldump --version of whichever client is doing the work: MariaDB and MySQL 5.x clients get --skip-ssl on loopback connections, MySQL 8 clients get --ssl-mode=DISABLED on loopback and PREFERRED elsewhere. Override with export_db_ssl_flag / import_db_ssl_flag.
  • MySQL 8 mysqldump against an older server gets --column-statistics=0 automatically.
  • db_fix_collation=auto rewrites utf8mb4_0900_ai_ci → utf8mb4_unicode_ci (and the _as_cs, _bin variants) when SELECT VERSION() on the local server says MariaDB or MySQL < 8.
  • The import prefix is session-level only; no SET GLOBAL, so no SUPER privilege is needed.
Files

What gets copied

Two settings control the file sync. sync_mode decides which part of the site, rsync_mode decides how existing local files are treated.

SettingValueEffect
sync_modefull (default)The whole web root minus the exclude list.
codeEverything except the uploads directory. Handy for a quick code refresh on a big media library.
uploadsOnly the uploads directory (wp-content/uploads or storage/app/public, or uploads_rel_path).
rsync_modesync (default)Transfer new and changed files. Local extras are kept.
ignore-existingOnly files that do not exist locally yet. This is what the original script always did.
mirrorLike sync, and deletes local files that are not on the remote (--delete).

Always excluded: .git/, *.sql, *.sql.gz, the local .maintenance file, and everything in config/rsync-exclude.txt (logs, archives, OS junk, cache and backup-plugin directories). Patterns there follow rsync's filter rules; a leading / anchors at the web root.

Also available
  • rsync_bwlimit (KB/s) and rsync_extra_opts (appended verbatim, e.g. --chmod=D755,F644).
  • --dry-run passes --dry-run to rsync, so the per-file log still shows what would transfer.
  • The uploads mode is built from nested include rules (--include=/wp-content/ --include=/wp-content/uploads/ --include=/wp-content/uploads/** --exclude=*) placed after the exclude list, so excluded subfolders stay excluded.
Command line

Run it your way

Everything on the command line has an .env equivalent, so wrapper scripts and CI jobs can drive it without arguments.

CommandWhen you want to
./migrate.sh --checkSee if everything is reachable before touching anything.
./migrate.sh --dry-runRehearse: SSH, table listing and an rsync dry run happen; every other command is printed with secrets masked.
./migrate.sh --only migrate-dbRefresh just the database (or any one step).
./migrate.sh --yes --skip sync-filesUnattended run without the file sync.
./migrate.sh --yes --with clear-web-rootUnattended full wipe and sync. Opt-in steps need --with, --only or run_<step>='true'.
./migrate.sh --env sites/client-a.envKeep one checkout and several site configs.
./migrate.sh --plainNo colours or emoji, for CI logs. Same as plain_output='true'.
./migrate.sh --list-stepsPrint the step ids, their mode and platforms.

Without a terminal and without --yes (cron, a CI job without a TTY) the script refuses to start rather than guess. A failing step stops the run and exits non-zero unless continue_on_error='true'.

Flags and their .env twins
  • --yes ↔ auto_confirm, --plain ↔ plain_output, --skip <id> ↔ skip_<id>='true' (legacy names kept: skip_file_sync, skip_db_import, skip_app_config, skip_cache_refresh, skip_maintenance), --with <id> ↔ run_<id>='true', skip_migrate_website='true' exits immediately for wrapper scripts.
  • Exit codes: 0 all good, 1 a step failed or the configuration is invalid, 2 bad command-line option, 130 interrupted.
Safety

What protects you

The script replaces a site's files and database, so the guard rails are the point.

Preflight first

Tools, SSH, remote root, both database logins. If any check fails, the run stops before anything is touched.

Local DB backed up

Before any table is dropped, the current local database is dumped to dumps/. Turn off with local_db_backup='false'.

Dry run

--dry-run prints every state-changing command, with secrets masked, and runs only the read-only parts.

Destructive steps are opt-in

Clearing the web root never happens under --yes unless named, refuses dangerous paths, and asks you to type the directory name interactively.

Secrets stay off the command line

MySQL passwords go through a mode-600 options file or stdin, SSH passwords through sshpass -e. Nothing shows up in ps.

Honest reporting

Each step's line in the report reflects its real exit status. A cleanup trap closes the tunnel, removes temp files and warns if maintenance mode was left on.

Also
  • wp-config.php is copied to wp-config.php.bak-<ts> before host-cleanup edits it.
  • SSH host keys use StrictHostKeyChecking=accept-new by default (ssh_strict_host_key accepts yes / no / accept-new).
  • Remote commands run with ssh -n so they can never swallow the script's own stdin.
Troubleshooting

When something looks off

SSL connection error, or "TLS/SSL error: self-signed certificate"

A MariaDB 11.4+ client talking to a server without certificates. Loopback connections already get --skip-ssl; for other hosts set export_db_ssl_flag='--skip-ssl' (MariaDB client) or '--ssl-mode=DISABLED' (MySQL client).

Unknown collation: 'utf8mb4_0900_ai_ci'

A MySQL 8 dump going into MariaDB or MySQL 5.7. db_fix_collation='auto' handles it when the local server is detected as such; force it with db_fix_collation='true'.

Unknown table 'COLUMN_STATISTICS' in information_schema

MySQL 8 mysqldump against an older server. --column-statistics=0 is added automatically for MySQL 8/9 clients; if you overrode the flags, add it back.

The SSH tunnel never comes up

Check the key's permissions (chmod 600) and that the remote allows TCP forwarding (AllowTcpForwarding yes in sshd_config). Switching to db_export_method='remote' avoids the tunnel entirely.

Bad configuration option: StrictHostKeyChecking=accept-new

OpenSSH older than 7.6. Set ssh_strict_host_key='yes' and accept the host key once by hand, or 'no'.

rsync: --info=progress2 unknown option

rsync older than 3.1 (the version bundled with macOS, for example). The progress bar is skipped automatically; install a newer rsync for progress output.

A plugin fatals during wp search-replace

Set wp_cli_extra_opts='--skip-plugins --skip-themes'.

The HTTP check warns but the site works in the browser

The local domain probably does not resolve from the machine running the script (a container, for instance). It is a warning, not a failure; set verify_http='false' to silence it.

Extending it
  • Layout: migrate.sh (CLI, step registry, main), lib/ (util, ui, env, ssh, db, wp, runner, preflight), steps/ (one function per step), config/ (lists), tests/ (bats suites and stub binaries).
  • New step: write step_<name>() in steps/<name>.sh, source it in migrate.sh, add a register_step line. Use run_cmd for state changes so --dry-run works, and return 1 on failure.
  • Checks: shellcheck -x migrate.sh and bats tests (54 tests, end-to-end against stubbed ssh/rsync/mysql/wp/php). CI runs both on Ubuntu and macOS.
